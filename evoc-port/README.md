# EVoC port

A dependency-free Rust port of
[EVoC](https://github.com/TutteInstitute/evoc) (Embedding Vector Oriented
Clustering, Leland McInnes / Tutte Institute), plus the parity fixtures it is
validated against, generated by running the reference Python implementation
(v0.3.1) at every deterministic seam of its pipeline.

The library crate lives at `src/rust/evoc-core/` so it ships inside the R
package (this directory is `.Rbuildignore`d); `parity/` here is a dev-only
crate holding the fixture tests and benchmark examples, keeping their
serde_json dependency out of the shipped tree. `cargo test --release` in
`parity/` runs the whole suite. The R surface is `shoal_evoc()`.
`GregorLueg/evoc-rs` served as a second reference implementation during
porting; the port here was written from scratch against the Python.

## The seam map

    data --(kNN)--> nn_inds, nn_dists
         --[S1 smooth_knn_dist]-------> sigmas, rhos
         --[S2 neighbor_graph_matrix]--> fuzzy graph (CSR)
         --(label prop + SGD embedding: stochastic, ARI-tested only)
         --[S3 build_cluster_layers]---> layers, strengths, persistence
              which decomposes into
         --[S4 boruvka MST]  --[S5 mst_to_linkage_tree]  --[S6 condense_tree]
         --[S7 leaves / labels / strengths]  --[S8 barcode / peak selection]

Six cases (`tiny`, `blobs2`, `blobs3_noise`, `uniform`, `dupes`, `nested`)
cover hand-checkable sizes, noise, no-structure, exact duplicates and nested
granularity. Two end-to-end cases (`emb_topics`, `emb_nested`) use
L2-normalised embedding-like input — EVoC's stated domain.

## evoc-core: the complete port

`evoc-core` (at `src/rust/evoc-core/`) is a Rust crate whose only dependency
is rayon — already vendored for shoal, so EVoC adds nothing to the CRAN size
budget — containing the full pipeline behind `pipeline::evoc()`:

- **Deterministic half, fixture-pinned bitwise or near-bitwise**: S1–S2
  (fuzzy graph), S4 (mutual-reachability MST via kd-tree Borůvka, with a
  Prim oracle), S5–S8 and the full S3 chain.
- **Stochastic half, ARI-bounded end-to-end**: NN-Descent (`nndescent`, the
  standard new/old local-join algorithm with the reference's cosine
  `-log2(dot)` metric and parameters), label-propagation initialisation
  (`labelprop`, the full recursive coarsening with the partition-expander
  upscaling and a PCA base case), and the SGD node embedding (`embedding`,
  the reference's reproducible block-synchronous kernel with its momentum,
  alpha and gamma schedules).

`cargo test` inside `parity/` runs everything: six seam groups, MST property
tests against the Prim oracle, and the end-to-end suite. All green against
reference v0.3.1. Unlike the reference, the whole pipeline — the stochastic
half included — is bitwise reproducible for a fixed seed regardless of
thread count: parallel passes only ever read frozen state and write disjoint
rows, with sequential index-order reduction where proposals contend.

Per-seed quality matches the reference statistically: on the `emb_topics`
case the reference scores 0.83–0.96 (mean 0.93) best-layer ARI over ten
seeds, the port 0.79–0.96 (mean 0.92) over eight; both have occasional tail
draws well below their typical score, which is why the end-to-end contract
bounds the mean as well as each tested seed. On `emb_nested` the port scores
0.98–1.0 across seeds.

## Measured against the reference (identical input bytes, warm numba, 4 threads)

Stage benchmarks best-of-3 (best-of-2 at n = 30k) on 4-d embeddings with 12
clusters + noise; "chain" is linkage → condense → extraction → persistence →
layers from a shared MST. Full-pipeline rows are single runs of
`pipeline::evoc()` vs `evoc.EVoC().fit_predict()` on L2-normalised 384-d
data with 10 clusters + noise, numba fully warm (`cache=True` hits), both
finding the true 10-cluster layer at ARI 0.94. Both columns from the same
container in the same session.

At full-pipeline scale both implementations are dominated by NN-Descent's
distance evaluations (3.5 s of the port's 5.67 s at n = 52.5k; the node
embedding is 1.1 s and everything else under 1 s combined). Reproduce from `parity/` with
`cargo run --release --example bench_full -- data.bin truth.bin 384` and
`--example stages` for the per-stage split.

The MST is a kd-tree Borůvka with the reference's structure — tree-queried
core distances, the kNN initialisation pass, component-aware queries with
per-component pruning bounds — parallelised with rayon for the per-point work
but reduced deterministically in index order, so unlike the reference (which
races on its pruning bound) the output is bitwise reproducible across runs and
thread counts. Correctness is held by the six MST fixtures plus property tests
against a brute-force Prim oracle over varied shapes, dimensions, min_samples
values, duplicates and tiny inputs.

NN-Descent's join proposals are computed in parallel and applied
sequentially in blocks of 8,192 points, which bounds the proposal buffer at
tens of MB regardless of n (peak RSS at n = 200k, d = 16 is 124 MB, down
from 762 MB when the whole dataset's proposals were buffered) at no change
in output: `tests/knn_pin.rs` pins the exact neighbour graph on both
end-to-end fixtures so any restructuring of the join has to be
output-preserving or deliberately re-pinned.

Remaining performance headroom, should it ever matter: the fuzzy graph is
still serial (parity with 4-thread numba as-is), and the chain has never
needed optimising.

## The contract a port must meet

- **S1–S2, S5–S8**: bitwise (f64 round-trip) equality with the stored outputs.
  Every one of these was executed twice at generation time and refused unless
  the runs agreed exactly.
- **S4 (MST)**: equality of the sorted weight sequence, to 1e-6. All minimum
  spanning trees of a graph share it, and mutual-reachability graphs are
  heavily degenerate (many pairs weigh exactly a point's core distance), so
  distinct equally-minimal trees are common even where the reference's own
  runs looked stable. The stored canonical edges exist for downstream
  chaining, not for endpoint comparison.
- **S3 (layer chain)**: bitwise from the stored canonical MST — the fixture is
  generated by replaying the reference chain from that exact tree, so it is a
  pure function of what it stores rather than of the reference's internal,
  order-unstable Borůvka run.
- **End-to-end**: on the stored input (base64 little-endian f32, row-major),
  scored as max-over-layers ARI against the stored truth, per seed. Two
  bounds from a 10-seed reference sweep: each tested seed must clear
  `min_ari_bound` (the reference's worst observed seed minus 0.02 — the
  reference has tail draws of its own, so the floor is generous by design)
  and the tested seeds' average must clear `mean_ari_bound` (the reference
  mean minus 0.04 — the check that actually catches a systematically weaker
  port). Bitwise parity is impossible: the node-embedding stage is
  stochastic in the reference itself.

## What generating these revealed about upstream (v0.3.1)

1. `parallel_boruvka(reproducible=True)` is not order-stable under tied edge
   weights, and with ties it can return different equal-weight MSTs across
   runs (observed on `dupes` and `nested`). A port should tie-break by
   `(weight, u, v)` and thereby be *more* deterministic than the reference.
2. Layer choice is not uniformly solvable: on nested structure the
   argmax-persistence pick can prefer a near-degenerate coarse layer
   (seed 42: k=2, ARI 0.16 while the base layer scores 0.98); on imbalanced
   topics the base layer over-fragments (ARI 0.61–0.83) and the persistence
   pick is right (0.92–0.96). End-to-end fixtures therefore score
   max-over-layers, and an R API should expose every layer rather than hiding
   the choice behind a single `labels`.
3. On raw low-dimensional non-normalised data the reference is weak and
   seed-unstable — cosine geometry is assumed. Input validation in any
   wrapper should steer users accordingly.

## Regenerating

    pip install evoc scikit-learn   # evoc==0.3.1 pinned in fixtures/manifest.json
    python3 generate_fixtures.py

Everything under `fixtures/` is overwritten. The generator aborts rather than
write any seam fixture that fails its determinism check, and rejects
end-to-end cases the reference itself cannot pass convincingly.
