# EVoC port fixtures

Parity fixtures for a planned Rust port of
[EVoC](https://github.com/TutteInstitute/evoc) (Embedding Vector Oriented
Clustering, Leland McInnes / Tutte Institute), generated by running the
reference Python implementation (v0.3.1) at every deterministic seam of its
pipeline. `GregorLueg/evoc-rs` serves as a second reference implementation;
the decision between porting from scratch and forking it remains open, and
these fixtures validate either.

## The seam map

    data --(kNN)--> nn_inds, nn_dists
         --[S1 smooth_knn_dist]-------> sigmas, rhos
         --[S2 neighbor_graph_matrix]--> fuzzy graph (CSR)
         --(label prop + SGD embedding: stochastic, ARI-tested only)
         --[S3 build_cluster_layers]---> layers, strengths, persistence
              which decomposes into
         --[S4 boruvka MST]  --[S5 mst_to_linkage_tree]  --[S6 condense_tree]
         --[S7 leaves / labels / strengths]  --[S8 barcode / peak selection]

Six cases (`tiny`, `blobs2`, `blobs3_noise`, `uniform`, `dupes`, `nested`)
cover hand-checkable sizes, noise, no-structure, exact duplicates and nested
granularity. Two end-to-end cases (`emb_topics`, `emb_nested`) use
L2-normalised embedding-like input — EVoC's stated domain.

## The contract a port must meet

- **S1–S2, S5–S8**: bitwise (f64 round-trip) equality with the stored outputs.
  Every one of these was executed twice at generation time and refused unless
  the runs agreed exactly.
- **S4 (MST)**: equality with the stored *canonical* form — edges as
  `(min(u,v), max(u,v))`, sorted by `(weight, u, v)`. Where
  `canonical_stable_across_runs` is `false`, tied weights admit multiple valid
  MSTs and only the weight multiset is binding.
- **End-to-end**: on the stored input (base64 little-endian f32, row-major),
  some returned layer must reach `min_ari_bound` against the stored truth —
  the reference's own worst seed minus a margin. Bitwise parity is impossible:
  the node-embedding stage is stochastic in the reference itself.

## What generating these revealed about upstream (v0.3.1)

1. `parallel_boruvka(reproducible=True)` is not order-stable under tied edge
   weights, and with ties it can return different equal-weight MSTs across
   runs (observed on `dupes` and `nested`). A port should tie-break by
   `(weight, u, v)` and thereby be *more* deterministic than the reference.
2. Layer choice is not uniformly solvable: on nested structure the
   argmax-persistence pick can prefer a near-degenerate coarse layer
   (seed 42: k=2, ARI 0.16 while the base layer scores 0.98); on imbalanced
   topics the base layer over-fragments (ARI 0.61–0.83) and the persistence
   pick is right (0.92–0.96). End-to-end fixtures therefore score
   max-over-layers, and an R API should expose every layer rather than hiding
   the choice behind a single `labels`.
3. On raw low-dimensional non-normalised data the reference is weak and
   seed-unstable — cosine geometry is assumed. Input validation in any
   wrapper should steer users accordingly.

## Regenerating

    pip install evoc scikit-learn   # evoc==0.3.1 pinned in fixtures/manifest.json
    python3 generate_fixtures.py

Everything under `fixtures/` is overwritten. The generator aborts rather than
write any seam fixture that fails its determinism check, and rejects
end-to-end cases the reference itself cannot pass convincingly.
